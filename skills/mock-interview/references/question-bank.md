# Question bank

Use these as inspiration, not a script. Prefer project-grounded versions (see `project-analysis.md`). Adapt difficulty to the level:
- **Junior:** fundamentals, explain own code, simple debugging, small coding task, light design ("how would you structure this feature").
- **Mid:** trade-offs, testing, performance, API/data design, ownership stories.
- **Senior:** architecture, scaling, reliability, security, mentoring, ambiguity, cross-team impact.

Suggested mix for **Standard (~10)**: 1 warm-up, 2 project deep-dive, 1–2 code & algorithms, 1–2 fundamentals, 1 debugging or AI-assisted, 1 system design, 1 live coding, 1–2 behavioral, 1 culture fit, then "questions for us". Scale down for Quick, up for Full. Respect the user's focus choice.

## Warm-up
- Tell me about yourself and what you're working on right now.
- Walk me through this project in two minutes: what it does, who it's for, and what you built.

## Project deep-dive / explain your code
- Why did you choose <framework/DB/library> for this project? What else did you consider?
- Walk me through what happens when a user <core action>, from click to database and back.
- Explain what `<function/file>` does and why it's written this way.
- What was the hardest bug or problem in this project, and how did you solve it?
- If you started this project again, what would you do differently?
- Where is the weakest part of this codebase right now? How would you improve it?
- How do you handle errors / loading states / invalid input in <feature>?
- How are secrets and API keys handled? What would happen if one leaked?
- How would you add <realistic next feature> to this codebase?

## Code & algorithms (from their own code)
Quote the snippet exactly (≤15 lines, with `path:lines`) from the "key code" in the project brief. Ask **one** of these per question, then follow up with another:
- **Explain line by line:** "Walk me through lines 12–30. What does each important line do, and why is it there?"
- **Trace it:** "If `ease=2.5` and `interval=6`, what does this return? Go step by step."
- **Name it:** "Is this a known algorithm or pattern? What is it called?" (spaced repetition, binary search, debounce, memoization, backoff…)
- **Complexity:** "What's the time complexity? What happens with 100,000 items?"
- **Edge cases:** "What happens if the list is empty / the value is null / two requests run at once?"
- **Why this way:** "Why sort before filtering? Why a `dict` and not a list here?"
- **Change it:** "How would you change this to also <realistic new requirement>?"
- **Find the bug:** if the brief noted a likely bug, ask "Do you see any problem with line 22?"
Without a project, use a short snippet in their stack (e.g. a `debounce`, a pagination helper, a `reduce` that groups items) and ask the same questions.

## Technical fundamentals (pick by stack)
- **JS/TS:** `==` vs `===`; closures; event loop and `async/await`; `let/const/var`; what TypeScript adds; `any` vs `unknown`.
- **Frontend/React:** props vs state; why `key` in lists; `useEffect` dependencies and common bugs; controlled inputs; when to use global state; how rendering/re-rendering works; SSR vs CSR.
- **Backend/API:** REST methods and status codes; idempotency; authentication vs authorization; sessions vs JWT; validation; rate limiting; pagination.
- **Databases:** SQL vs NoSQL; indexes and when they hurt; joins; transactions/ACID; N+1 problem; migrations.
- **Python:** list vs tuple vs dict; mutable default args; generators; virtualenvs/packaging; GIL basics.
- **General:** Big-O of common operations; HTTP request lifecycle; what happens when you type a URL; Git branching, merge vs rebase; environment variables.
- **Security:** XSS, CSRF, SQL injection, storing passwords (hashing + salt), CORS.

## Debugging
- A user reports "the page is blank" in production, but it works locally. What do you do, step by step?
- An API call works sometimes and fails sometimes. How do you investigate?
- Your app became slow after the last deploy. How do you find the cause?
- Here's an error message / stack trace from your stack: what does it tell you and where would you look?

## AI-assisted coding (important for vibe coders)
- How do you use AI tools in your workflow? Where do they help most and where do they fail?
- How do you verify that code generated by AI is correct and secure before you ship it?
- Tell me about a time AI gave you wrong or bad code. How did you notice and what did you do?
- If I removed AI tools for a day, which parts of this project could you still change confidently?
- How do you make sure you understand code you didn't write line by line?
- What would you never let an AI do without reviewing it (e.g. auth, payments, migrations, deleting data)?

## System design (scale to level)
- **Junior-light:** How would you structure the backend for a simple to-do/notes app with users? What tables/endpoints?
- Your project suddenly gets 100× more users. What breaks first? What do you change, in which order?
- Design a URL shortener / a chat feature / a notification system / file upload with thumbnails.
- How would you add caching here? What can go wrong with caching?
- How would you make this feature work if the external API is down or slow?
- How do you deploy without downtime? How do you roll back?

## Live coding (10–20 min, no AI)
Pick one matching level and stack; relate to the project if possible.
- **Junior:** reverse words in a sentence; count character frequency; validate a password with rules; remove duplicates preserving order; FizzBuzz variant; group items by a field; implement `debounce`.
- **Mid:** parse and summarize a log file; LRU cache; merge overlapping intervals; flatten a nested object; rate limiter; paginate an array with metadata; write a small API handler with validation.
- **Senior:** design + implement a small in-memory job queue with retries; implement a concurrency-limited `mapAsync`; refactor a messy function from the user's project and explain the choices.
- Afterwards ask: complexity, edge cases, how you'd test it.

## Behavioral (expect STAR)
- Tell me about a project you're proud of. What exactly was your part?
- Tell me about a time you were stuck for a long time. How did you get unstuck?
- Tell me about a mistake you made that had consequences. What did you learn?
- Tell me about a time you disagreed with someone (teammate, client, reviewer).
- Tell me about a time you had to learn a new technology fast.
- Tell me about a time you had too much to do and had to prioritize.
- How do you handle code review feedback you disagree with?

## Culture fit & motivation
- Why do you want to work as a developer / in this role?
- Why this company / this kind of product? (Ask them to pick a realistic target company type.)
- Where do you see yourself in 2–3 years?
- How do you keep learning? What did you learn recently?
- What kind of team and manager do you work best with?
- What are your salary expectations? (Coach: research the range, give a range, mention flexibility.)
- What's your biggest weakness as a developer?

## Closing
- Do you have any questions for us? (Evaluate their questions; suggest 3 strong ones if they have none: e.g. "What does onboarding look like in the first 90 days?", "How do you review and ship code?", "What would success look like in this role after 6 months?")
